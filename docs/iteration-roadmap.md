# GameWeare 迭代路线（仅表示顺序）

此表按依赖关系排序，不给具体日期。**已实现**表示仓库已有代码；**待验收**表示有实现但尚无目标环境证据；**待建设**表示仍需补齐。历史代码和本机短时测试不等同生产可用。

| 顺序 | 阶段 | 当前状态 | 进入下一阶段的产物或验收 |
| --- | --- | --- | --- |
| ① | 确定产品边界：用户描述游戏、AI 生成、发布、游玩；旧 Python 后端归档 | 已实现 | 单一 GameWeare 仓库与 Java 后端主线 |
| ② | 建立 Spring Boot 模块化单体、Flyway、MySQL、Redis、RabbitMQ、MinIO 和 React 页面 | 已实现 | 注册登录、目录、上传、创建、版本与试玩基础链路 |
| ③ | 固化一致性与安全基础：幂等任务、事务 Outbox、Worker 租约、发布隔离、会话撤销、生产密钥和 AI 出口限制 | 已实现；生产环境待验收 | 多实例重复消息、越权、重试与配置失败用例通过 |
| ④ | 接入 AgentScope Java：五种模式、官方子智能体、每任务隔离沙箱、项目记忆与用量记录 | 本地实现；真实模型和 Kubernetes 待验收 | Docker 模拟模型全流程，随后真实模型工具调用与集群隔离验证 |
| ⑤ | 提高生成质量：HTML 校验工具、明确错误诊断、游戏后独立封面 ReAct、优化保留原封面 | 已实现；真实模型可玩率待测 | 可编译、可启动、可操作的游戏与封面端到端样本 |
| ⑥ | 完善创作者体验：任务列表/轨迹、审批、续作、发布、游玩、管理员工作台与可读名称 | 已实现；浏览器自动化待补 | 用户账号从创建到游玩的回归用例 |
| ⑦ | 扩展高并发业务：缓存、热榜、关注、签到、生成券秒杀和同券并发核销 | 已实现；持续负载待验收 | 库存、券归属与任务状态的对账和故障注入结果 |
| ⑧ | 打通真实外部依赖：用户模型、官方券模型、Google OAuth、图片输入与完整试玩 | 待验收 | 不使用 Mock 的可复现端到端记录；失败原因可追踪 |
| ⑨ | 验证真实 Kubernetes 沙箱与多实例恢复：controller、RuntimeClass、网络策略、Pod 重建和记忆恢复 | 待验收 | 跨任务隔离、故障恢复、无密钥泄露、无重复发布的证据 |
| ⑩ | 生产可用性：持续压测、指标与告警、账单对账、数据库/对象联合备份恢复、安全审查 | 待建设/待验收 | 以实际测试结果记录吞吐、P95、库存对账与恢复时间 |
| ⑪ | 作品集交付：整理架构证据、演示路径、简历中的指标来源和已知限制 | 待整理 | 任何对外性能数字都能追溯到相应脚本、环境与结果 |

建议每完成一阶段，就更新对应的 [架构](architecture.md)、[后端](backend.md)、[对接](frontend-api.md) 或 [Agent](agent.md) 文档，不再新增按周、按天的临时计划。下一阶段优先从 ⑧ 开始；⑨ 和 ⑩ 的验收结果决定何时适合对外宣称生产可用。
